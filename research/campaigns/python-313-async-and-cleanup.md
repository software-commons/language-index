# Python 3.13.0 asynchronous execution and cleanup

Five additional Python claims have independent support in the exact 3.13.0 reference. They cover asynchronous context exit, the asynchronous iterator protocol, coroutine return values, asynchronous generator close behavior, and executed control transfers leaving an active `finally` clause. The final point concerns an executed transfer that leaves the clause. An inner-loop break may stay within it. [Research receipts](../../sces/artifacts/python-313-async-proof-research.jsonl) · [Independent review receipts](../../sces/artifacts/python-313-async-proof-review.jsonl)

The initial `async for` proposition is held. Its positive description of iterator exhaustion is supported, but its scope also separated target assignment from the exhaustion guard. The reference’s illustrative outline places assignment inside that guard. In the exact 3.13.0 CPython compiler, the guard ends before target assignment is compiled. Supplementary 3.13.5 probes are recorded separately and carry no 3.13.0 implementation claim. This discrepancy is retained at the original claim and source spans.
