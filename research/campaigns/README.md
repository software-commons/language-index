# Language population research

This directory records discovery methods, coverage decisions, and gaps. The candidate ledger records leads and dispositions. Canonical entities and qualified claims use the separate registry and SCES paths documented in the maintenance guide.

The [November 22, 2026 census](census-2026-11-22.md) records the current public intake, measured intersections, original ledger recovery attempt, and limitations.

## Predecessor reconciliation

Inspect the exact Regex Conformance census documentation, forecast, universe registry, and discovery contracts. Search accessible predecessor working areas for the external census artifact. Compare any matching candidate bytes with the published digests before treating them as recovered. Preserve the results of the search and distinguish inspected historical counts from independently reconstructed leads.

Inspect the Programming Productivity Atlas overlay and design decisions at a pinned revision. Preserve original IDs and relevant disagreements. Treat discovery and measurement classifications as lead provenance. Verify language identity, implementation boundaries, editions, dialects, and lineage against sources suited to those claims.

## Discovery and individual review

Record every scoped lead, its precise origin, and a reasoned disposition. Expand the search beyond predecessor inputs using official specifications, language and compiler references, literature, and archives. Track which pathways address historical, academic, proprietary, international, and domain-specific languages. Preserve inaccessible and unresolved leads. Record the actual cutoff, inclusion criteria, deduplication procedure, exclusions, and open searches in each coverage snapshot.

For each investigated candidate, distinguish research on identity and history, design, specification and editions, and implementation or ecosystem relationships. Record an explicit uncertainty when a dimension remains unexplored or has no accessible controlling source. Use the pinned SCES task and separate verification executions before claiming qualification.

## Batch verification and assembly

Freeze the exact records before giving the independent verifier the claim statements, hashes, and original source locators. Keep the primary interpretation out of the verifier's input until after direct source inspection. An independent run records an assessment for each dependency and reports its claim-level verdict and challenges.

Use `research/tools/export_codex_receipts.py` to export a safe trace and run descriptor for each completed turn. Pass those files and the frozen assessments to `research/tools/assemble_sces_batch.py`. The assembler writes a new staging directory. It binds each assessment to exact claim bytes and each dependency to a digest-matched source acquisition. It retains negative verification outcomes. Use `--hold` to retain a review and withhold disposition for a claim with a documented unresolved interpretation. Validate the resulting records against the pinned SCES checkout before integration. The approver must still inspect the underlying trusted capture and evaluation. Keep raw private rollout transcripts outside Git.
