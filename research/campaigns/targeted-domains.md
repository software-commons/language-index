# Targeted public discovery pass

Cutoff: 2026-11-22 (America/Chicago). This provisional pass supplements the broad predecessor and tooling catalogs. It targeted regions and technical areas that English and general-purpose language catalogs can undercount.

## Procedure

1. Search publisher documentation with native terms such as `日本語プログラミング言語`, `아희 언어의 명세`, `КуМир`, `pseudocódigo`, and `langage de programmation`. Check Japanese project manuals, Korean Aheui documentation, Russian research publications, Spanish documentation, and French manuals. For Qalb and Wenyan, use the original project repositories.
2. Search formal methods, hardware design, shader, and configuration specifications. Inspect documents or file listings from language maintainers and their standards publishers, including IEEE, Accellera, ITU, W3C, and Khronos. Seek smaller embedded, query, constraint, interactive-fiction, and configuration DSLs in the same developer ecosystems.
3. For GitHub-issued locators, resolve the repository's advertised HEAD to a full commit and confirm the exact README path at that revision. Use named or dated publisher manuals and standards where available. Treat live manuals as locators for follow-up source acquisition.
4. Traverse all project entries in PLOC's 2023 Chinese-language blue book. Preserve the report's language and tooling candidates without inheriting its admission rules. Printed page locators follow below. Retain overlapping origins so a later reconciliation can distinguish corroborating leads and genuinely different entities.

## Boundaries and follow-up

- Do not conflate Kulics K with the K semantic language, the PLOC Z label with ISO Z notation, or the PLOC NASL label with a similarly named language based on spelling. Keep HDL family, edition, implementation, and intermediate representation decisions open. Treat the name of an implementation repository as a source locator, then investigate the separately governed language.
- The pass identifies examples across the selected strata. Coverage remains incomplete for additional languages and geographies, local educational systems, closed proprietary systems, and work accessible only through preservation archives or subscription standards. The PLOC method favors available and active projects. Search visibility can favor GitHub projects and current English summaries even when discovery uses native-language terms.
- Printed PLOC page numbers were read from the public report's table of contents. The local download could not establish a trusted TLS connection, so no local binary hash or PDF viewer-fragment mapping was recorded. The whole report URL and printed section/page identifiers are retained for reacquisition.
- Reacquire exact sources at a durable revision and inspect original-language passages before making claims about identity or semantics. For implementation and draft repositories, establish the scope of the material before treating it as an authority. Repeat direct inspection in the separate verification run and retain actual SCES receipts for release candidates. No lead in this batch establishes comprehensive language coverage.
