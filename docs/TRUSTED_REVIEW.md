# Trusted Codex technical review

Language Index requires protected pull requests and two independent controls. SCES governs scientific verification of exact claim revisions. The proposed GitHub App check governs review of the exact integrated change. Publication still requires an authorized decision about the exact frozen commit and asset digests under [publication control](PUBLICATION.md).

## Implementation and trust boundary

[The issuer patch](../research/review/shared-issuer.patch) adapts the shared Software Commons issuer in the License Index candidate at `28d5614577b0f3bb09041bf2e45bac7da725cc82`. Apply it to the reviewed baseline in a separately protected deployment. The files in this repository are review material. The installed issuer must run trusted, pinned code and configuration from outside any checkout under review.

The issuer reads the PR from GitHub and fetches its test-merge ref without checking out or executing candidate files. It checks the ordered base and head parents and captures the complete base-to-test-merge binary diff, exact tree, SCES tree inventory and hashes of the adoption, selection, claims, and qualification artifacts present in that tree. A fresh Codex execution inspects the patch and selected SCES artifacts as data. The audit retains the exact binding and tool transcript. It demands successful exact-byte witnesses for the patch and each provided SCES artifact. These witnesses identify inspected material. Scientific review still depends on the independently recorded direct source inspections, applicability assessments, and challenges in SCES.

The production caller requires source-bound SCES and registry CI successes on the exact test-merge SHA before and after technical review. The current Language Index PR checks appear on the raw head, so commissioning must establish the exact test-merge check placement. Changes to the control paths require a separately authorized exact test-merge SHA in issuer-owned configuration. The issuer creates the check on the test-merge SHA after review, then validates its App ID and decision digest against GitHub's response. Changes to head, base, merge SHA, or target require another review. GitHub enforcement of the combined check set must be demonstrated before cutover.

## Deployment and commissioning

1. Confirm the protected issuer revision, trusted Codex launcher digest, and dedicated App installation with the organization owner. The App must be private, organization-owned and installed only for `software-commons/language-index`. Use the shared issuer's exact commissioning permissions. The installation token must be short-lived and scoped to this repository. Preserve its issue audit without retaining any token or key in the repository.
2. Use a hardened POSIX issuer account with external private audit storage and configuration. The shared launcher drops to a dedicated unprivileged UID and GID without supplementary groups. It restricts Codex tools to the staged review inputs and approved runtime paths and disables tool network access. Give that account its own private home and Codex authentication. Verify actual credential and audit isolation on the host before issuing any GitHub check.
3. Configure `repository`, `app_id`, `audit_dir`, `codex`, `codex_sha256`, `model`, `reviewer_uid`, `reviewer_gid`, and `reviewer_home` in issuer-owned configuration. Record any protected-control authorization separately as `authorized_control_merge` with the exact test-merge SHA. Keep that field absent for ordinary review. Stream the installation token over standard input only after the trusted issuer requests it.
4. Add the strict required context `Software Commons / Codex technical review` from the dedicated App while retaining the existing Code Owner rule and Actions checks. Use the shared commissioning command with `--repository software-commons/language-index --gh-owner --pull NUMBER --app-id ID --decision-sha256 SHA256`. Run the installation-token scope observation through protected stdin. An observed configuration match is an input to the live tests.
5. Demonstrate GitHub enforcement on the exact combined context set. Verify that GitHub accepts a genuine current test-merge result with both existing CI checks. Exercise absent and failed results, same-name status from another source, an isolated head change, a base-only update with unchanged head, and retargeting. Verify that raw-head approvals never substitute for the valid test-merge result. Use an owner-authorized test surface with equivalent rules if the active human approval prevents isolating this behavior. Keep the current protection if check placement or exact freshness fails.
6. After independent assessment and explicit owner authorization, change only the incompatible Code Owner approval rule. Preserve required pull requests, the App and Actions checks with their sources, deletion and force-push protection, and the empty bypass list. Use `--after-cutover` for the owner check and repeat the live positive and negative cases. Keep Code Owners for ownership visibility. Restrict App configuration, required checks, issuer credentials, and publication control changes to the same protected change process.
