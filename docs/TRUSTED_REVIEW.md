# Trusted Codex technical review

Language Index uses protected pull requests. SCES governs scientific verification of exact claim revisions. The proposed GitHub App requirement governs technical review of the exact integrated change. Publication separately requires authorization of the frozen commit and artifact digests. [Publication control](PUBLICATION.md)

## Issuer and trust boundary

[The issuer patch](../research/review/shared-issuer.patch) adapts the shared License Index issuer at `24e5858889c7081be86149cb6cc431c665a2a4c0`. Use that exact revision on the organization-controlled deployment host. The adapter SHA-256 is `3094daecf0d5b89222a25d421957ad844004bef74d38ff37ed29823da04f7d96`. Keep the issuer code, configuration, audit records, GitHub credentials, and App private key beyond the reach of pull-request code and the reviewer identity. [Shared issuer commissioning](https://github.com/software-commons/license-index/blob/24e5858889c7081be86149cb6cc431c665a2a4c0/docs/CODEX_GATE.md)

Approval has two phases. Queue admission reviews the exact GitHub test merge and publishes a check to the single-parent PR head. That result only admits the PR to the mandatory queue. Final review binds a separate decision to the live singleton merge-group commit. The issuer checks the exact queue ref and ordered base and head parents, verifies genuine successful SCES and Registry runs and job checks on that commit, and rechecks live protection, PR and queue evidence before posting. Retained audit evidence identifies both decisions, reviewed commits, policy artifacts, and source checks.

When a candidate has an active SCES publication, the shared issuer stages the exact selection, qualification report, payload, and the selected records and evidence they depend on, including inherited material. It compares used inputs with those at the frozen source commit and binds the staged file digests to the review decision. The review trace must include fresh byte proofs for the staged files. Scientific verification and authorization to release are separate requirements. Changes to workflow, schema, testing, validation or other control paths require separate authorization for the commit reviewed in each phase.

Registry tests run in a separate worker from the required validation job in the proposed Domain workflow. Both workers install SCES dependencies from the pinned policy checkout using isolated Python. The issuer recognizes the existing combined Registry job and the proposed isolated Registry tests job. Its final gate preserves the two required contexts and their GitHub Actions source, currently App ID `15368`. Checks on the head alone cannot establish the final queue decision.

## Commissioning

1. Register one private Software Commons App for the shared issuer and select the authorized repositories. Grant repository Checks write, Commit statuses write and Metadata read. Keep App installation and key custody outside review execution. Issue separate, repository-scoped tokens. Before writing a check in either review phase, the issuer requires the token to list exactly the configured repository by numeric ID and full name. [GitHub App registration](https://docs.github.com/en/apps/creating-github-apps/registering-a-github-app/registering-a-github-app) · [App installation](https://docs.github.com/en/apps/using-github-apps/installing-a-github-app-from-a-third-party)
2. Run the issuer on a controlled POSIX host with a separate unprivileged reviewer UID and GID, reviewer-private home and authorized Codex login. Pin the executable and model. On Linux, keep the bubblewrap helper in a trusted runtime path. The review profile grants read access to the exact pinned executable and staged inputs alongside its minimal runtime paths. Make the issuer's validated GitHub CLI available with owner-readable rulesets and bypass actors. The issuer uses GitHub CLI only for GET requests. Test access isolation before issuing a live check. Configure the private issuer settings documented in the shared issuer, including `repository: software-commons/language-index`. Provide a short-lived repository-scoped installation token through the protected stdin provider. [Ruleset visibility](https://docs.github.com/en/rest/repos/rules#get-a-repository-ruleset)
3. Rehearse the protected reviewer runtime using `--rehearsal-config` and verify the reviewer’s access boundaries. The production issuer pins `main` and `Software Commons / Codex technical review`. For an owner-authorized trial, independently review and pin a separate issuer copy to the trial branch and trial check context. Bind that trial context to its exact numeric App ID and configure a singleton merge queue for the trial branch. Require each check context once with its expected numeric source, strict status checks, and enforcement at ref creation. Both workflow callers subscribe to `merge_group`. Keep mandatory pull requests, existing approval requirements, deletion and force-push protection, and the empty bypass list throughout commissioning. [Singleton queue rule](../research/review/merge-queue-rule.json) · [Merge queue settings](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/configuring-pull-request-merges/managing-a-merge-queue) · [Required check placement](https://docs.github.com/en/pull-requests/how-tos/merge-and-close-pull-requests/troubleshooting-required-status-checks)
4. In protected issuer settings, set `commissioning_phase` to `trial` for the trial branch, `additive` for production with its original approvals, or `final` after the owner-authorized cutover. Language Index requires Code Owner review and zero ordinary approvals in trial and additive phases, and zero ordinary approvals with Code Owner review disabled in the final phase. Set the additional `authorized_cutover_ruleset` to the integer `27874363` only after the owner authorizes that ruleset's final cutover. The issuer compares the live effective approval rule with the protected phase before review and at each pre-issuance freshness check. The decision records that phase and the observed rule.
5. Run `python -B -m tools.review_gate review NUMBER --issuer-config CONFIG --queue-admission` using the appropriate pinned issuer copy. After GitHub produces a successful live merge-group workflow run, run a separate protected review with `--queue-run RUN_ID`. Set `authorized_control_merge` only for the separately approved exact test-merge or queue-merge SHA. Run the read-only owner preflight with `python -B -m tools.review_commission --gh-owner --repository software-commons/language-index --commissioning-phase PHASE --pull NUMBER --app-id ID --queue-run RUN_ID --admission-sha256 ADMISSION_DIGEST --decision-sha256 FINAL_DIGEST --installation-token-stdin`. In the final phase, supply `--authorized-cutover-ruleset 27874363` to compare readback against the commissioned rule. Provide the repository-scoped installation token through protected stdin.
6. Demonstrate the positive path and failure with missing or wrong-source decisions, new heads, base-only changes, retargeting, replaced queue refs or CI attempts, and reuse of a checked merge object. GitHub can merge promptly after a successful final check. Preserve live observations before issuance and compare the landed tree and check records afterward. Obtain the separate owner authorization before changing the Code Owner requirement. Keep the Code Owners file and repeat checks after the authorized cutover.

## Continuous integration and branch cleanup

Start each new research or development segment from synchronized `main`. Keep the branch scoped to records, checks, documentation, and artifacts directly affected by that segment. Preserve exact source captures and independent scientific review. Validate against the actual protected base and open a focused PR to `main` as soon as the segment is ready. Use separately reviewable checkpoints when the full binary diff would exceed the shared issuer's 8 MiB capture limit.

Bind the authenticated technical review and required GitHub checks to the exact current PR and merge group. Merge eligible work through the protected workflow. Confirm the reviewed tree and frozen evidence ancestry on `main`. Research that is still provisional uses the corresponding registry state. Publication has a separate qualification and release authorization for exact assets. [Publication control](PUBLICATION.md)

After integration, compare every branch tip considered for cleanup with live `main`. Check that each exact tip and its required frozen source revisions are reachable. Record how any superseded PR’s unique evidence and historical reports reached `main`, then close the covered PR and remove only its contained remote and local branch. Prune remote tracking refs, synchronize the designated checkout, and verify a clean worktree before starting the next segment. Preserve any blocked branch with unique commits.
